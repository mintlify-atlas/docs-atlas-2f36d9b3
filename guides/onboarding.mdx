Onboarding is a one-time flow every new Coder completes on their first login. It captures your soft skills profile through a self-assessment, then immediately generates your first AI-powered 4-week learning plan tailored to your results.

<Note>
  Onboarding is required for all new Coders. The system detects `first_login = true` on your account and redirects you to `coder/onboarding.html` before you can access your dashboard. You cannot receive a learning plan until the soft skills assessment is submitted.
</Note>

## Who needs to complete onboarding

Any Coder whose `users` record has `first_login = true` must complete onboarding. This includes:

- New registrations via email + OTP
- New sign-ins via Google or GitHub OAuth (social auth skips the OTP step but still requires the soft skills assessment)

Once you submit the assessment and onboarding completes, the system sets `first_login = false` on your account so you are never redirected again.

## The full onboarding flow

<Steps>
  <Step title="Register your account">
    Submit the registration form at `auth/register.html`:

    ```bash
    POST /api/auth/register
    ```

    ```json
    {
      "email": "you@example.com",
      "password": "yourpassword",
      "fullName": "Your Name",
      "role": "coder",
      "clanId": "Turing"
    }
    ```

    The server creates your account with `first_login = true` and `otp_verified = false`, then immediately sends a 6-digit OTP to your email via SMTP.
  </Step>

  <Step title="Verify your email with the OTP">
    You are redirected to `auth/email-validation.html`. Enter the 6-digit code from your email:

    ```bash
    POST /api/auth/verify-otp
    ```

    ```json
    {
      "email": "you@example.com",
      "code": "847291"
    }
    ```

    <Warning>
      The OTP expires after **15 minutes**. If it expires before you enter it, request a new code using:

      ```bash
      POST /api/auth/resend-otp
      ```

      ```json
      { "email": "you@example.com" }
      ```

      The server invalidates the old code and sends a fresh one to your email.
    </Warning>

    On success, `otp_verified` is set to `true` on your account, a session is created, and you are logged in. The response includes your `firstLogin: true` flag.
  </Step>

  <Step title="Get redirected to onboarding">
    Because `first_login = true`, the server (or the frontend auth check) redirects you to `coder/onboarding.html` instead of the dashboard. This redirect happens automatically after OTP verification and on every subsequent login until onboarding is complete.
  </Step>

  <Step title="Complete the soft skills assessment">
    The onboarding page presents the five-dimension self-assessment. Rate yourself on a scale of 1 to 5 for each dimension:

    | Dimension | What it measures |
    |---|---|
    | Autonomy | Your ability to work independently without guidance |
    | Time management | How well you plan and stick to deadlines |
    | Problem solving | How you approach bugs, blockers, and unfamiliar problems |
    | Communication | Clarity when asking for help or collaborating |
    | Teamwork | Your effectiveness in group work or pair programming |

    You also select your preferred **learning style**:

    | Style | Description |
    |---|---|
    | `visual` | Diagrams, charts, and visual representations |
    | `auditory` | Listening, discussion, and verbal explanation |
    | `kinesthetic` | Hands-on practice and direct experimentation |
    | `mixed` | Adapts across multiple styles |

    These scores and your learning style shape every AI-generated plan and focus card you receive. Answer honestly — lower scores in areas like autonomy result in more guided activities, which is the right support, not a penalty.
  </Step>

  <Step title="Submit the assessment">
    When you submit, the assessment is written to the `soft_skills_assessment` table:

    ```bash
    POST /api/diagnostics
    ```

    ```json
    {
      "autonomy": 2,
      "time_management": 4,
      "problem_solving": 3,
      "communication": 3,
      "teamwork": 4,
      "learning_style": "visual"
    }
    ```

    All five dimension values must be integers between 1 and 5. The `learning_style` must be one of the four valid enum values. Submissions that fail validation return HTTP 400.
  </Step>

  <Step title="Complete onboarding">
    After the assessment is saved, the frontend calls:

    ```bash
    PATCH /api/auth/complete-onboarding
    ```

    This sets `first_login = false` on your account. You will not be redirected to onboarding again on future logins.
  </Step>

  <Step title="Receive your first learning plan">
    Immediately after onboarding completes, the system generates your first personalized plan using the `interpretive` plan type — which relies entirely on your soft skills data since you have not yet accumulated Moodle progress.

    The plan generation request is sent to the Python AI microservice:

    ```bash
    POST /api/coder/plan/request
    ```

    ```json
    {
      "plan_type": "interpretive",
      "current_week": 1
    }
    ```

    Plan generation is asynchronous — the server responds immediately with `{ "requested": true }` while the AI processes your profile in the background. Your plan will be ready within a few seconds.

    <Tip>
      The `interpretive` plan is generated from your soft skills profile alone. Once you have Moodle data (academic scores, completed weeks, struggling topics), you can request an `analytical` plan that incorporates your academic performance for a more targeted result. Ask your Team Leader or revisit your dashboard after your first Moodle sync.
    </Tip>
  </Step>

  <Step title="Go to your dashboard">
    Once your plan is ready, you are redirected to `coder/dashboard.html`. Your active plan is displayed with its targeted soft skill, plan type, and generation date. You can start working through Day 1 immediately from `coder/assignment.html`.
  </Step>
</Steps>

## Social auth path

If you register or sign in with **Google** or **GitHub**, the OTP email verification step is skipped. OAuth users are authenticated directly and `otp_verified` is set to `true` automatically.

However, social auth does not bypass the soft skills assessment. If your account has `first_login = true`, you are still redirected to `coder/onboarding.html` after the OAuth callback. You must complete the assessment before you can access your dashboard.

The OAuth callback logic in `socialAuthSuccess` checks `first_login` and redirects to either `coder/onboarding.html` or `coder/dashboard.html` accordingly.

## What happens if you skip it

The `checkOnboarding` middleware on all coder routes enforces that onboarding is complete. If you attempt to access `GET /api/coder/dashboard` or any other coder endpoint while `first_login = true`, the request is rejected. The only way to unlock the dashboard is to complete the soft skills assessment.

See [Soft skills assessment](/features/soft-skills-assessment) for more detail on how your scores are used to generate plans.
